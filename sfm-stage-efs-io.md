SfM Stage EFS I/O Map
=====================

**System:** AWS Batch Structure-from-Motion (SfM) pipeline data flow reference

This reference captures what each AWS Batch SfM stage reads and writes on the shared EFS volume (`DATA_ROOT/<tour_id>`). Use it to reason about hand-offs between jobs and to verify the artifacts that should exist before/after a stage runs. Infrastructure wiring (queues, IAM, Batch definitions) is intentionally out of scope.

**Note:** This document describes the EFS input/output patterns of the OpenSfM reconstruction pipeline stages (Stage 1–5), which are separate infrastructure components from any specific application repository.

Shared Layout
-------------

- Every stage resolves the tour workspace to `DATA_ROOT/<tour_id>` and expects imagery under `images/`. Stage 1 creates the folder before downloading from S3 and subsequent stages assume the same tree is mounted.  
- Unless noted, paths below are relative to `DATA_ROOT/<tour_id>`. Submodel work happens under `submodels/submodel_*`, reusing the same dataset structure inside each subfolder.

Stage 1 – Preprocess & Feature Extraction
-----------------------------------------

**Consumes**

- Initial images and optional masks from S3 (`<user_id>/uploads/<tour_id>/` and `.../masks/`).

**Writes / updates on EFS**

- `images/`, `masks/` – created/populated from S3.
- `config.yaml`, optional `camera_models_overrides.json` – copied/generated by `configurator.py`.
- `exif_overrides.json` – GPS overrides seeded for downstream EXIF extraction.
- `exif/`, `camera_models.json`, `features/`, `matches/` – populated by OpenSfM during `extract_metadata`, `detect_features`, `match_features`.

Stage 2 – Submodel Reconstruction
---------------------------------

**Consumes**

- Stage 1 outputs (`images/`, `config.yaml`, `exif/`, `features/`, `matches/`, `camera_models.json`, etc.).

**Writes / updates on EFS**

- `submodels/` tree – created when image count exceeds threshold.
- Inside each `submodels/submodel_*`:
  - `tracks.csv`, `reconstruction.json`, `rot_trans_matrix_npy/` – produced by `create_tracks` and `reconstruct`.
  - `mesh` artifacts (`mesh/`, intermediate undistorted/depth outputs) from `mesh`.
  - `stats/`, `reports/` from `compute_statistics` and `export_report`.
- Optional upload of the aggregated `rot_trans_matrix_npy/` folder next to the tour root for downstream stages.

```18:38:docker/stage2_submodels/reconstructor.sh
if [ "${num_images}" -gt 300 ]; then
  bin/opensfm create_submodels "${DATA_DIR}"
  for SUBMODEL in "${DATA_DIR}/submodels"/submodel_*/; do
    bin/opensfm create_tracks "${SUBMODEL}"
    bin/opensfm reconstruct   "${SUBMODEL}"
    bin/opensfm mesh          "${SUBMODEL}"
    bin/opensfm compute_statistics "${SUBMODEL}"
    bin/opensfm export_report "${SUBMODEL}"
  done
fi
```

Stage 3 – Full Reconstruction
-----------------------------

**Consumes**

- Stage 1 dataset tree (and optionally submodels produced in Stage 2).

**Writes / updates on EFS**

- Root-level `tracks.csv`, `reconstruction.json`, `rot_trans_matrix_npy/`, and `profile.log`.
- Existing `reports/` folder refreshed with reconstruction statistics.

Stage 4 – Undistort & Depth Products
------------------------------------

**Consumes**

- Root reconstruction outputs (`reconstruction.json`, `tracks.csv`, `rot_trans_matrix_npy/`).
- Optional submodel trees (`submodels/submodel_*`) when present.
- Requires images in `images/`.

**Writes / updates on EFS**

- `undistorted/` (and, for submodel runs, each `submodels/submodel_*/undistorted/`).
- `depth_output/` and merged `rot_trans_matrix_npy/` when submodels are aligned.
- `merged_combined.ply` (merged point cloud).
- Keeps the aggregated reconstruction files alongside the tour root for later zipping.

Stage 5 – Statistics & Reporting
--------------------------------

**Consumes**

- Reconstruction outputs (`reconstruction.json`, `tracks.csv`, `rot_trans_matrix_npy/`), undistorted data, EXIF metadata, and submodel merge products from Stage 4.

**Writes / updates on EFS**

- `stats/` (including `stats/stats.json`), refreshed by `compute_statistics`.
- `reports/report.pdf` (and related assets) from `export_report`.
- `shot_headings.json`, `gps_corrected.json`, `gps_corrected_with_headings.json`, `shot_headings_with_dropped.json`, `headings_interpolated.png`, `shot_info/` from the post-processing scripts.
- Keeps the previously generated `undistorted/` in the final Stage 5 bundle.
